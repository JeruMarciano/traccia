# Bundle measurement for v0.1 — what the scan cost in shipped bytes

**Date:** 2026-08-02
**Commit:** `0bd7743051f2ff5a1669c91f0ae76e62797d104e` (branch `v0.1-external-map`)
**Host:** macOS 24.6.0, Apple silicon, rustc 1.97.1, release profile

The preflight (`docs/decisions/2026-08-01-v0.1-preflight.md` §2) measured `chromiumoxide`'s cost
with a temporary probe that touched `Browser::launch`, `Page::execute`, `Connection::submit_command`
and `Browser::connect` — deliberately an upper bound, and it said so: "Task 12 must re-measure
rather than carry this number forward." Task 7 has since written the real `cdp.rs`, following the
preflight's own advice at §1 — protocol types plus a raw `Connection`, `Browser` never touched, so
`Browser::connect`'s reqwest/hyper call path is compiled in (unconditionally, from
`chromiumoxide`'s own `Cargo.toml`) but never called. This is that re-measurement.

## Commands

```bash
source "$HOME/.cargo/env"
npm run tauri build

stat -f '%z %N' src-tauri/target/release/traccia
find src-tauri/target/release/bundle -name '*.dmg' -exec stat -f '%z %N' {} \;
du -sk src-tauri/target/release/bundle/macos/Traccia.app
du -sk dist

cd src-tauri && size -m target/release/traccia | head -20
cargo tree -e normal -i hyper
```

Windows figures come from the same source the 2026-07-31 measurement used: the `report the shipped
size` step of the `bundle (windows-latest)` job in `.github/workflows/build.yml`, artifact
`traccia-windows-latest`. At the time this document was written that number was recorded as
pending, rather than estimated. **Measured 2026-08-02** from CI run 30760492982 (commit 38c7c52,
after the Windows launch-wait fix that run forced): `Traccia_1.0.0_x64-setup.exe` =
**1,214,106 bytes**, against the 2026-07-31 Windows baseline of 1,124,383 — a delta of
+89,723 (+8.0%), the same order as the macOS delta (+7.2%) and attributed the same way
(chromiumoxide).

## Against Electron

**60.4× smaller** — 1,647,339 against 99,452,988, a saving of 97,805,649 bytes per download. The
macOS download is 1.57 MiB, still comfortably inside the 10–15 MB the Tauri port was justified by.

The 2026-07-31 measurement was 64.7×. This build is 60.4× for the reason set out below: the
numerator grew because the CDP client is now load-bearing, not because anything regressed.

### Attribution: chromiumoxide, and nothing else

`git log --oneline -- src-tauri/Cargo.toml` between the 2026-07-31 commit and this one shows
exactly two changes: Task 0's preflight, which pinned `chromiumoxide = "0.7"` and added
`futures-core`, and no other dependency touch since. `futures-core`'s own budget-comment entry
(Task 7) already establishes it ships zero marginal bytes — `cargo tree -e normal -i futures-core`
shows it was already reachable three ways through `chromiumoxide` before the line naming it
existed, so declaring it changes only what the crate is permitted to name, not what the linker
sees. That leaves the entire +183,504 / +111,012 delta attributable to `chromiumoxide` becoming
reachable from `run()` — Task 7's `cdp.rs`, which drives `chromiumoxide::cdp` protocol types and
`chromiumoxide::conn::Connection` directly.

`cargo tree -e normal -i hyper` confirms the shape the preflight predicted: `hyper` 1.11.0 is
compiled in via `hyper-util` → `reqwest` 0.12.28 → `chromiumoxide` 0.7.0, even though `cdp.rs`
never calls `Browser::connect` (the one call site that would use it). The HTTP stack's bytes are
paid whether or not the call happens, because `chromiumoxide` depends on `reqwest`
unconditionally — this is the same finding preflight §1 made, now visible in a build that actually
ships the crate.

### Against the preflight's own estimate

The preflight measured a deliberately maximal probe: **+1,380,736 bytes of binary / +718,410 of
`.dmg`** reachable from `run()` without `Browser::connect`, rising to +1,581,216 / +836,366 with it
on a live path. This build's real cost — **+183,504 / +111,012** — is roughly one seventh of that
lower bound. The preflight said the realistic Phase 2 figure "should land below these figures" if
a later implementation followed §1's advice (protocol types plus a raw connection, no `Browser`).
Task 7 did exactly that, and the gap between the probe's +1.38 MB and the real +0.18 MB is the
measured cost of not touching `Browser`, `Page`, `Target` or any of chromiumoxide's own handler
machinery — only the CDP type definitions and a connection primitive were ever linked from
reachable code.

## What this document does not have

**The Windows number was pending when this document was written** — the environment the task ran
in could not push a branch or trigger CI, and no number was estimated in its place. It was
measured on 2026-08-02 exactly the way this section prescribed (the `report the shipped size`
step of `bundle (windows-latest)`, CI run 30760492982) and is now in the table above:
1,214,106 bytes, +8.0% over the stale 2026-07-31 figure of 1,124,383. This section is kept as
written for the record of what was and was not known at measurement time.

## Verdict

Still an order of magnitude inside the 10–15 MB the port was justified by, at 1.57 MiB for the
largest platform figure measured (macOS). The scan feature — the CDP client that makes the map
possible — cost 111,012 bytes of `.dmg`, about 108 KiB, which is the honest price of a typed
protocol library over hand-rolling every CDP command's params struct by hand. The Windows figure
remains to be read from CI before this can be called complete for both platforms.
